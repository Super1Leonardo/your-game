# Твоя Игра

Браузерная версия интеллектуальной викторины для компании друзей за одним устройством. Проект реализован на **Svelte 5** с использованием **Runes**.

## Технологический стек

- **Фреймворк:** SvelteKit (Static Adapter)
- **Core:** Svelte 5 (Runes: `$state`, `$derived`, `$effect`)
- **Стилизация:** Tailwind CSS 4 + DaisyUI
- **UI Компоненты:** Melt UI (Headless accessibility)
- **Тестирование:** Playwright
- **Язык:** TypeScript

## Архитектура приложения

- Проект построен по принципу модульного монолита с четким разделением ответственности.
- Управление состоянием (State Management)
- Логика игры полностью отделена от UI и находится в src/lib/state. Используется реактивность Svelte 5 Runes.
- gameStore.svelte.ts - Глобальный стор, хранящий состояние игры (игроки, вопросы, таймеры, текущий раунд). Состояние автоматически синхронизируется с localStorage через $effect, что позволяет переживать перезагрузку страницы (F5).
- devStore.svelte.ts - Состояние режима разработчика.

## Структура проекта

1. src/routes/ - страницы приложения
2. /setup - настройка сессии, количества игроков
3. /editor - редактор вопросов.
4. /game - основное игровое поле.
5. /final - логика финального раунда.
6. /results - страница с итогами игры
7. src/lib/components/ - UI компоненты, разбитые по доменам (game, editor, setup, ui). Все компоненты используют семантическую верстку.
8. src/lib/utils/ - чистые функции бизнес-логики (answerChecker, timer, keyboardManager).
9. src/data - папка с вопросами

## Модули и компоненты

#### components/editor:

1. QuestionCard.svelte - карточка для обычного вопроса на странице Редактора вопросов
2. RoundEditor.svelte - сетка из QuestionCard на странице Редактора вопросов, используется на вкладках "Раунд 1" и "Раунд 2". Взаимодействует с QuestionCard путем цикла
   {#each ... as ... } и передачи внутрь каждого вопроса
3. SpecialQuestionCard.svelte - карточка для "котов в мешке" и финального вопроса на странице Редактора вопросов. Отличается от QuestionCard отсутствием поля "стоимость" и наличием поля "тема"
4. SpecialsEditor.svelte - сетка из SpecialQuestionCard на странице Редактора вопросов, используется на вкладке "Спец. вопросы". Взаимодействует с SpecialQuestionCard путем цикла {#each ... as ... } и передачи внутрь каждого вопроса

#### components/game:

1. Board.svelte - Основное игровое табло. Генерирует сетку раунда, взаимодействует с BoardCell путем цикла {#each ...} для отрисовки тем и стоимостей.
2. BoardCell.svelte - Отдельная ячейка табло. Отображает название темы или стоимость вопроса. Обрабатывает клик для перехода к экрану вопроса, меняет стиль, если вопрос уже сыгран.
3. AvgQuestion.svelte - Логика отображения обычного вопроса. Включает в себя таймер, обработку нажатия клавиш игроками (кто первый) и поле ввода ответа.
4. Auction.svelte - Компонент для спецвопроса "Аукцион". Auction управляет состоянием торгов, взаимодействует с AuctionUI путем руны $props
5. AuctionUI.svelte - Компонент для спецвопроса "Аукцион", отрисовывает интерфейс ставок и кнопок "Ва-банк"/"Пас"
6. Cat.svelte - Компонент для спецвопроса "Кот в мешке". Реализует логику выбора игрока (кому передать вопрос) через PlayerDropdown и ввод ставки.
7. PlayerPanel.svelte - Панель игроков. Отображает аватары, имена, текущий счет и индикатор активности (кто отвечает). В Dev-mode позволяет менять счет вручную.
8. Timer.svelte - Визуальный круговой таймер. Принимает время в секундах и событие onTimeUp для завершения хода.
9. PlayerDropdown.svelte - компонент из Melt UI. Используется для выбора игрока, которому передается кот в мешке
10. DevModeButtons.svelte - кнопки для режима разработчика, позволяющие пропустить или просто закрыть вопрос
11. GameDialog.svelte - компонент Dialog из Melt UI. Диалоговое окно, используется при игре Кота в мешке и Аукциона
12. Header.svelte - обычный header с элементом смены темы, функцией выхода в главное и включения режима разработчика, а также показывающий номер раунда

#### components/setup:

1. PlayerCountSelector.svelte - выбор количества игроков
2. PlayerInputRow.svelte - строка настройки одного игрока (включая выбор профиля и аватар).
3. PlayerSetup.svelte - главный файл, который просто собирает всё вместе.
4. GamePackManager.svelte - Блок управления пакетом вопросов. Реализует функционал Drag & Drop загрузки JSON-файла и кнопку экспорта текущего пакета.

#### components/final:

1. FinalBets.svelte - Первый этап финала. Интерфейс для ввода скрытых ставок игроками по очереди.
2. FinalQuestion.svelte - Второй этап финала. Отображает текст вопроса и запускает 60-секундный таймер для каждого игрока по очереди.
3. FinalReveal.svelte - Третий этап финала. Экран подведения итогов: последовательно раскрывает ставки, ответы игроков и правильный ответ, определяя победителя.

#### components/ui:

1. Upload.svelte - Компонент загрузки изображений (аватаров). Построен на базе Melt UI, поддерживает предпросмотр загруженной картинки.
2. ThemeSwitcher.svelte - Переключатель темы оформления (светлая/темная), использует контроллер DaisyUI.
3. Toaster.svelte - Глобальный менеджер уведомлений. Отрисовывает всплывающие сообщения (ошибки, успехи), которые отправляются через функцию addToast, также является компонентом Melt UI.
4. DevModeSwitch.svelte - Переключатель режима разработчика.

## Реализованные экстрафичи

- **Персонажи игроков** (максимум 2 балла)  
  Перед началом игры участник может выбрать аватар или загрузить своё изображение, которое отображается рядом с его именем и счетом и сохраняется в течение игровой сессии.
- **Импорт и экспорт пакетов вопросов** (максимум 4 балла)  
  Пользователь может сохранять текущий набор вопросов в файл и загружать новые наборы из файла. При загрузке выполняется проверка формата и содержимого, а при ошибках показывается понятное сообщение. Также можно хранить несколько наборов и переключаться между ними.
- **Редактор тем и вопросов** (максимум 5 баллов)  
  В игре есть встроенный редактор, позволяющий добавлять новые темы и вопросы.
- **Улучшенная проверка ответа** (максимум 3 балла)  
  Проверка ответов реализована с учётом возможных неточностей: разной формулировки правильного ответа, регистра, опечаток и тому подобного.
- **Настройка числа игроков** (максимум 3 балла)  
   Перед началом игры можно настроить число игроков - от двух до разумного максимума. Список игроков корректно связывается с остальными функциями: профилями, аватарами и статистикой.
- **Темная тема и смена тем оформления** (максимум 1 балл)  
   Интерфейс поддерживает несколько тем оформления и возможность переключаться между ними.
- **Анимации** (максимум 2 балла)  
   Более живой интерфейс с анимацией выбора ячейки, открытия вопроса и других ключевых действий.
- **Сохранение профилей игроков** (максимум 2 балла)  
  Игроки могут создавать и сохранять локальные профили с именем, выбранным персонажем и купленными предметами. При запуске новой игры можно выбрать существующий профиль или создать новый. Профили сохраняются между сессиями и при необходимости могут быть удалены.

## Использование LLM

Искуственный интеллект был использован для следующих задач:

1. Инкапсуляция, то есть вынесение части кода из уже готов файлов/компонентов, чтобы в итоге файл был меньше 150 строк
2. Написание тестов с Playwright. В этом проекте я первый раз писал тесты на нем, так что пришлось спрашивать у нейронки
3. Дебаг написанного кода
4. Добавление комментариев в коде, чтобы не забыть какая функция что делает
5. Частично написание этого файла (README.md)
6. Мелкие рутинные задачи, типа внедрение написанных компонентов в код, исправление стилей и тому подобное
